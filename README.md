# MediDrone

Minimal, real, installable PWA for out-of-hospital cardiac arrest SOS triggering.
No mock data, no demo mode, no fake GPS, no database of its own — the app is
stateless and talks entirely to the external MediDrone backend over REST. The
only local state is the one-time user profile (localStorage).

## Stack

- Next.js 16 (App Router) + TypeScript (strict)
- Tailwind CSS 4
- Hand-rolled PWA: `public/manifest.webmanifest` + `public/sw.js`
- No auth, no accounts, no admin, no history — 2 screens only

## Run

```bash
npm install
cp .env.example .env.local   # set NEXT_PUBLIC_API_BASE_URL
npm run dev                  # http://localhost:3000
```

Production:

```bash
npm run build
npm start                    # SW + manifest are active in prod only
```

## Env

- `NEXT_PUBLIC_API_BASE_URL` — public base URL of the MediDrone backend,
  inlined by Next at build time. Never hardcoded in source. No trailing slash.
  If unset at build time, the app shows a visible "dispatch service not
  configured" error instead of silently hanging.

## Backend contract (REST)

- `POST {base}/api/v1/emergencies`
  body: `{ "lat": number, "lng": number, "accuracy": number,
          "timestamp": ISO8601, "name": string, "phone": string,
          "aadhaar_last4": string }`
  → `2xx { "emergency_id": string }`
- `GET {base}/api/v1/emergencies/{emergency_id}` → JSON whose `status` field is
  one of `RECEIVED, DRONE_ASSIGNED, MISSION_GENERATED, DISPATCHED, EN_ROUTE,
  APPROACHING, ARRIVED, AED_DELIVERED, COMPLETED, FAILED`.

Status is polled every 5 s until a terminal state (`COMPLETED`/`FAILED`); poll
failures are visible and back off to a 30 s max. The API origin is never cached
or intercepted by the service worker.

## Screens

1. **Setup** (first launch only) — full name, phone, Aadhaar last 4 digits
   ("for identification only"). Saved client-side only; future launches go
   straight to Home. Editable later from Home.
2. **Home / SOS** — one tap: real `getCurrentPosition`
   (`enableHighAccuracy: true`, `maximumAge: 0` — no stale/cached fixes) →
   POST → status screen. No forms, no confirmation dialogs between press and API
   call.
   - Geolocation denied/unavailable/timeout → visible error + Retry + manual
     "Call emergency services (112)" link. A 15 s app-side watchdog guarantees
     a stuck platform can never produce a silent hang.
   - Network/timeout failures while POSTing auto-retry with backoff (1 s, 2 s,
     4 s) and are surfaced attempt-by-attempt; API error responses (4xx/5xx)
     are shown immediately, never swallowed.
3. **Status** (`/emergency/{id}`) — shows emergency_id, live state, seen
   transitions, the location that was sent, and polls until a terminal state.

## PWA

- Manifest: standalone, portrait, theme color, 192/512 + maskable icons
  (generated by `npm run icons` with sharp).
- Service worker: versioned shell cache (`medidrone-shell-vN`). Precaches `/`
  and the manifest; navigations are network-first with a cached-shell fallback;
  `/_next/static/*` and icons are stale-while-revalidate; `sw.js` itself is
  served `max-age=0, must-revalidate` so updates propagate. Cross-origin (API)
  requests are never touched.

## Tests

Real-browser e2e (Playwright) — setup/localStorage gating, one-tap SOS with a
real geolocation → POST → status polling flow, denied/timeout geolocation,
POST failure, poll failure/backoff, PWA install/offline shell. The app itself
has no stub: `e2e/mock-backend.mjs` is a test-only HTTP server that mimics the
backend contract while developing against the documented placeholder
`http://localhost:8000`; nothing in `app/`, `components/`, `lib/` knows about it.

```bash
npm run test:e2e                    # dev flow suite (expects mock on :8000)
npm run build
npx playwright test --config=playwright.pwa.config.ts   # prod SW/offline suite
```

## Deploy (Vercel)

`vercel.json` ships with the repo (framework `nextjs`, `npm run build`, and a
`max-age=0, must-revalidate` header on `/sw.js` so PWA updates propagate).

1. [vercel.com](https://vercel.com) → **Add New… → Project → Import Git
   Repository** → select `sharang-naladkar/MediHelpApp`.
2. On the import screen set:
   - **Root Directory:** `./` (repo root)
   - **Framework Preset:** Next.js (auto-detected)
   - **Build Command:** `npm run build` (default)
   - **Install Command:** `npm install` (default)
   - **Node.js version:** 22 (default, satisfies `>=20.9.0`)
3. **Environment Variables → Add:**
   - `NEXT_PUBLIC_API_BASE_URL` = `https://medihelp-production-35ca.up.railway.app`
   - Apply to **Production** (and Preview if you want staging hits the same API).
   - *Note: `NEXT_PUBLIC_*` is inlined into the client bundle at build time —
     after changing it, trigger a **redploy**.*
4. **Deploy.** First build ≈ 1–2 min. The phone then opens the generated
   `https://<project>.vercel.app` URL directly — no preview token, no sandbox.
5. **Production branch:** the MediDrone app lives on
   `arena/01a07f88-medihelpapp`; `main` still holds the old scaffold. Either
   merge the open PR into `main`, or in **Settings → Git → Production Branch**
   set `arena/01a07f88-medihelpapp` (and redeploy).

Recommended after deploy: `https://<project>.vercel.app/sw.js` should return
200 with `Cache-Control: public, max-age=0, must-revalidate`, and the
manifest should load at `/manifest.webmanifest`.

## Connectivity verification (real backend)

1. Set `NEXT_PUBLIC_API_BASE_URL` to the real URL and redeploy/rebuild.
2. On a real phone/device (PWA-installed if possible): fill setup, press SOS on
   cellular data (not just Wi-Fi), confirm a real `emergency_id` returns and the
   status screen moves through a real transition (even `RECEIVED → FAILED`
   proves the round trip).
3. In browser devtools → Network, confirm the POST body carries real GPS
   coordinates (not `0,0` or a stale value).
